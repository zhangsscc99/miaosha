# 01 用 Redis Lua 做原子扣库存

这一章在一台 4 核虚拟机上，用一个内存上限 64MB 的 Redis，把秒杀扣库存的决策压完。面试口径和费用在上一层的 [技术报告](../REPORT.md)。这里是复现步骤、脚本和原始结果。

## 复现

依赖本机的 `redis-server` 7 和 Go 1.22。脚本会自己拉起 Redis，测完关掉。不要对已经有数据的实例运行，`FLUSHDB` 会清掉当前库。

```bash
bash run.sh
```

`results/*.json` 是 2026-11-12 这次跑出来的原始输出。`pass: true` 才算这组成立。非原子扣减那一组的通过条件相反：它必须表现出超卖或账对不上。

## 资源

`redis-64mb.conf`：绑定 127.0.0.1:6379，`maxmemory 64mb`，`save ""`，默认关闭 AOF。

`redis-32mb-6379.conf` 和 `redis-32mb-6380.conf`：两个进程各 32MB，用来看加进程，而不是加内存。

压测进程和 Redis 在同一台机器。机器是 4 vCPU，Redis 7.0.15。成功路径把 Redis 打到大约 99% CPU，售罄路径也是。RSS 在售罄时约 10MB，在写入 69.6 万个胜出用户时约 49MB。

## 脚本

| 文件 | 作用 |
| --- | --- |
| `lua/stock.lua` | 先看用户是否已成功，再判断库存，然后 `DECR` + `SADD`。返回 0 售罄、1 成功、2 重复 |
| `lua/soldout.lua` | 库存已经是 0 时只做一次 `GET` |
| `lua/unlock.lua` | `GET` 到的 value 等于 token 才 `DEL` |
| `lua/ratelimit.lua` | 固定窗口。拒绝时不加计数 |

Redis 单线程执行整段 Lua，所以判断和扣减之间不会插入别的命令。不需要再拿一把分布式锁。

## 结果摘要

正确性，库存 100，400 个用户每人 10 次：

- 非原子 GET/SET：卖出 400，库存剩 74（`results/unsafe-correct.json`）
- Lua：成功 100，重复 900，售罄 3000，库存 0，耗时 24 毫秒
- 分布式锁：结果和 Lua 相同，耗时 3.43 秒，忙等 702169 次

吞吐，统计窗口 4 秒：

- Lua 成功路径，16 连接：**138581 QPS**，p99 ≤ 200 微秒，CPU 99.7%（`lua-tps-w16.json`）
- 同一路径打开 AOF everysec，32 连接：从 137331 降到 **118892 QPS**
- Lua 售罄，16 连接：**194907 QPS**，p99 ≤ 200 微秒
- 128 连接的售罄路径降到 172035 QPS，p99 ≤ 2 毫秒
- 分布式锁成功扣减：**1263 QPS**（4 秒内成功 5051 次）
- 本地售罄标记：Redis 命令 60203 → **578**，两边都正好卖出 100（`local-shed.json`）
- HTTP 本地拒绝，32 客户端：**120452 QPS**，p99 ≤ 1 毫秒
- HTTP 里每次执行售罄 Lua：**66092 QPS**
- 一个进程两个售罄 key：195007 QPS。两个进程合计 64MB：**326011 QPS**，1.69 倍
- SQLite WAL 单行，`synchronous=FULL`：**29654 QPS**。这是乐观于 MySQL 的对照

进程内原子读是 3169 万 QPS。那是没有 HTTP 的数字，接口容量用 12.0 万这一档。

## 扩到 10 万 / 100 万 / 1000 万点击 QPS

典型秒杀的库存远小于点击。5000 件按 13.9 万成功 QPS 计算，决策大约 36 毫秒，之后都是售罄流量。应用台数用 HTTP 本地拒绝的 120452 QPS 去除。Redis 规划用官方单分片参考值 10 万 QPS；实验列用本机 19.5 万。价格是目录价：Redis 1GB 标准版 0.21 元/小时 = 151.2 元/月（阿里云帮助中心算例），4 核 8G 按社区转述的 c9i 月价 940 元。

| 点击 QPS | 应用（4 核 8G） | 每个点击都进 Redis（官方 10 万/分片） | 本地标记生效后 |
| --- | --- | --- | --- |
| 10 万 | 1 台，另加 1 台备用 | 1 × 1GB | 1 × 1GB。月费 2×940+151.2 = 2031 元 |
| 100 万 | 9 台 | 10 × 1GB，1512 元 | 1 × 1GB。月费 8611 元。Redis 少付约 1361 元/月 |
| 1000 万 | 84 台 | 100 × 1GB，15120 元 | 1 × 1GB。月费 79111 元。Redis 少付约 14969 元/月 |

1000 万点击如果应用也按「每次打 Redis」的 66092 QPS 去买，要 152 台，比 84 台多大约 63920 元/月。和 Redis 少付的 14969 元加在一起，大约少 7.9 万元/月。6.6 万 QPS 是客户端、服务端和 Redis 挤在同一台 4 核机器上测到的，Redis 独立部署后这个差额会变。

同一个库存 key 不能靠增加分片提高 QPS。两个 key 在一个进程里仍然是 19.5 万。要超过单核，把库存按用户拆桶，再放到多个进程。这次双进程只压了售罄读。

单行数据库在 SQLite FULL 上是 2.97 万 QPS。1000 万点击是它的 337 倍。升配去不掉行锁。胜出的那几千笔订单才需要落库，那是下一章的事。

## 本轮明确没做的

MySQL、主从切换、跨机器延迟、成功路径的双进程加速、多实例准入额度、消息队列、Docker、Kubernetes。
