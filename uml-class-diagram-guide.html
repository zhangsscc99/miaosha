UML 2.5 · Class Diagram

UML 类图符号手册

一条线画成实线还是虚线、末端是空心三角还是实心菱形，含义完全不同。按「类框 → 六种关系 → 多重性 → 易混点」看一遍，常见的类图符号就都能读了。

空心三角指向父类或接口，表示 is-a。
菱形永远在「整体」那一端，表示 has-a。
开放箭头指向被依赖、被调用的一方，表示 uses。

Class Box

类框的解剖

一个类画成三格：类名、属性、方法。成员前面的符号表示可见性，后面的写法遵循同一套语法。

记号含义说明
+public任何地方可访问
-private仅本类内部可见
#protected本类及子类可见
~package同一个包内可见
/namederived派生属性，由其他属性计算
namestatic属于类，不属于某个实例
nameabstract抽象类或抽象方法，名称用斜体

成员写法

属性+ name: Type = default
方法+ name(param: Type): ReturnType
泛型List<Order>

可见性符号写在最前面，类型在冒号后，默认值用等号。约束写在花括号里，例如 {readOnly}。

Relationships

六种关系

先记三句话：三角指向父类或接口，菱形留在整体端，开放箭头指向被依赖者。前四种按耦合由弱到强排列，后两种属于继承轴。

依赖

Dependency

一个类在方法里临时用到另一个类：参数、局部变量、返回值或静态调用。被依赖方变化时，使用方可能受影响。

OrderService 调用 PayService，但没有把它保存为成员变量。

void submit(Order o, PayService pay)

关联

Association

两个类之间有长期的结构联系，通常落成成员变量。两端可以标注角色名和多重性。

一个 User 对应 0..* 个 Order；buyer 和 orders 是两端扮演的角色名。

private List<Order> orders;

聚合

Aggregation

弱的「整体—部分」关系。部分可以脱离整体单独存在，整体销毁时部分通常不受影响。

Team 由 Member 组成；成员离开团队后仍然是一个 Member。

private List<Member> members;

组合

Composition

强的「整体—部分」关系。部分随整体创建和销毁，脱离整体没有独立意义。

Order 由 OrderItem 组成；订单一删，订单项随之删除。

private final List<OrderItem> items = new ArrayList<>();

泛化

Generalization

子类继承父类的属性和方法，是 is-a 关系。空心三角指向父类。

AdminUser 是一种 User，继承了 User 的属性和方法。

class AdminUser extends User

实现

Realization

类兑现接口定义的契约。虚线加空心三角，三角指向接口。

AlipayPay 实现了 PayService 声明的支付能力。

class AlipayPay implements PayService
i 实线表示结构关系，虚线表示临时关系或实现。线上的开放箭头只说明「能从哪里走到哪里」，不改变关系种类。

Multiplicity

多重性

多重性写在关联线的一端，描述「另一端的 1 个对象，对应这一端的多少个对象」。

写法含义
1恰好 1 个
0..10 或 1 个
*0 个或多个，等同于 0..*
1..*至少 1 个
2..52 到 5 个
n恰好 n 个
→ Order 1 —— 0..* OrderItem 读作「一个订单对应零个或多个订单项」：数字标在它描述的那一端，不要写反。

Other Notation

其他常见符号

除了关系线，这几个记号也经常出现在类图里。

接口：棒棒糖画法

空心圆表示这个类提供的接口，实线把圆连到类。类框画法则在名称上方写 «interface»。

包

带标签的文件夹形状，用来给类分组。包之间也可以画依赖。

注释

折角矩形加一条虚线，用来补充说明，不参与类之间的结构。

枚举

«enumeration» 类框里列出有限个常量，方法栏通常省略。

文字记号

抽象类类名用斜体，或者标注 {abstract}。
构造型«service»、«entity»、«repository» 写在类名上方。
模板类右上角画一个虚线小框写 T，如 Repository<T>。
约束{ordered}、{unique}、{readOnly} 写在元素旁边。
接口（类框）名称上方一行 «interface»，名称可以用斜体。

Common Mistakes

最容易画错的几处

这些符号长得像，含义却差得很远。先看末端装饰，再看线型。

符号正确含义常见误用
实线 + 空心三角泛化 / 继承三角画向子类
虚线 + 空心三角实现画成实线，变成继承
实线 + 空心菱形聚合菱形画在「部分」那一端
实线 + 实心菱形组合与聚合混用，忽略生命周期
虚线 + 开放箭头依赖当成成员变量的关联
实线 + 开放箭头可导航关联以为箭头代表继承
! 判断聚合还是组合，只看生命周期：部分能独立存在，用空心菱形；部分随整体消亡，用实心菱形。
! 多重性标在它描述的那一端：Order 1 —— 0..* OrderItem 是一个订单对应多个订单项。写反是最常见的错误。
